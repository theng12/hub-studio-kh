# Changelog

Plain-language changes appear first in each release and feed the app’s What’s New. Engineering details follow under Technical notes.

## 0.6.258 — 2026-11-23

- **Hub carries nothing of yours when it leaves this Mac.** The project's own files no longer name a person's home folder or a machine on your network, so the project can be published without exposing either. Nothing you use changes: every path still resolves on your Mac, and the drive kit behaves exactly as before.
- **The drive kit's old-file cleanup takes its list from you.** Preparing a drive now asks for the names of the retired kit's files (`KIT_RETIRE_ITEMS`). If that list is not given, the step refuses and says so instead of guessing which files on the drive were the old kit's; an empty list means there is nothing to retire.

### Technical notes
- Tracked tree scanned clean for `/Users/<name>`, `.ts.net` hosts and the estate hostname prefix (172 files): paths now come from `Path.home()`/`$HOME`/the environment at runtime, documents and evidence were reworded, six evidence PNGs dropped a path-bearing EXIF block (pixels untouched), and fixtures were renamed consistently. Configs that named the old checkout resolve to the current one. No behaviour changes; every developer-schema path still skips when absent.
- `packaging/prepare-kit.sh` takes `KIT_RETIRE_ITEMS` (newline-separated, spaces allowed): unset refuses with exit 1, set-but-empty means nothing to retire, and each named item still moves into that volume's `_trash` under the same name.
- `packaging/yue2-runtime/build.sh` drops two build-machine files the runtime checker refuses — the uv CPython distribution's `BUILD` stamp at the runtime root and the local install's `uv_cache.json` in its dist-info. No runtime content changes.
- `packaging/stage_voice.py` — the YuE2 runtime pin moves to the tree the tracked builder produces (`e2e4d1df…`), from the 2026-11-21 value (`9a47de18…`). The old tree cannot be reproduced by the current uv/CPython toolchain and no copy survives. A first replacement taken from `.build` turned out to be a build that never finished normalisation: it carried `/Users/<name>` 21 times in its generated sysconfig and once in `libpython`'s install name, and the gate's home-path check found both. `packaging/rebuild_build_inputs.sh` now refuses a tree in that state, and the qualified tree is one the builder finished — neutraliser included — proven by a real generation on this Mac (8.0 s, 48 kHz stereo, 3,071,576 bytes, sha256 `44a4481e…`, peak footprint 9.8 GB). Evidence in `lead/release-0.6.258-20261123/RECEIPT.md`.
- `components/hub/developer_image_runner.py` — a stop that lands while the child is exiting records `interrupted`, not `failed`. `shutdown()` sets the cancel event and then kills the child; a child that died with a half-written output was read as `output_invalid` before the cancel was seen, so the operator's own stop settled as a failure. The runner now re-reads the cancel event after its poll loop and takes its reason as the stop code — the only place the race could be closed, because the ledger refuses to rewrite a terminal row. Gate run 8 caught it under load (one test); after the fix the shutdown test settled `interrupted` in 8 of 8 repeats.

## 0.6.256 — 2026-11-21

- **A new Mac answers only itself until you give it a role.** A freshly installed Hub used to open up on every private network it was on — LAN and Tailscale — from the first launch. Now it listens on this Mac only. Picking a role (Controller or Node) or joining a group opens its private and Tailscale networks, and the Connections page says exactly what is open. The machine type is remembered, so a Controller keeps its networks after a restart. The "Follow this Mac's networks" switch and a pinned address list still do exactly what you set.
- **Relay now installs and updates itself like Hub.** Relay 0.3.33 has been on the feed but on no Mac: the updater's app list never included it. Every Mac now carries a Relay entry that can update automatically, so a Mac installs Relay from the feed the same way it installs Hub. Macs already set up gain the entry on their next Hub check, and their existing settings are left as they are.

### Technical notes
- `native/ShellCore.swift` — the first-run `defaultListenHost()` (every private address) is gone; `automaticListenHost(keeping:current:inFleet:)` returns loopback when `inFleet` is false. At launch `inFleet` is a saved controller address, a remembered role of controller/node (`lastKnownRole`, a new saved field), or an explicit choice (`listenHostChosen`, a new saved field set by `--fleet-mode`, `--listen-auto` and the operator's own switch — an explicit "reach me" outranks the gate). A saved list that already holds real addresses counts as a role that predates this build, so an upgrade never closes a Mac that was reachable. `followFleetNetworks()` opens the list when a role is picked or a group joined and leaves a pinned list alone; `StudioHub.observeFleetRole`/`rememberController` call it and mark a restart needed; `leaveFleetNetworks()` closes the list again when the Hub reports Standalone or this Mac leaves its group (`onFleetLeft`), and neither touches a pinned list or an explicit choice. The role is saved so a controller — which has no controller address — reopens its networks after a restart. Tests in `tests/native/main.swift`: fresh install loopback, no-role gate on the policy, picking a role opens, a pinned list survives, leaving closes, a controller reopens, an upgraded reachable Mac keeps its networks, `--listen-auto` keeps its explicit choice.
- `components/hub/backend/khu_agent.py` — `known` gains `kh.relay.desktop` → (`relay`, `app-dmg`); Relay's row is `automatic` and is written with an empty `bundlePath` when the bundle is absent, so the agent installs it from the feed (the same route a fresh feed-only app takes). `Bootstrap.reconcile_apps()` adds missing rows to an already-enrolled config at each five-minute check, keeping every saved row as written — the table is otherwise written only at enrolment, which is why an app added now would never reach the fleet. `packaging/kit-khu/apps.json` and `packaging/kit-khu/khu-install.py` carry the same entry for the drive kit. ## 0.6.255 — 2026-11-20

- **A failed Hub update now gets another try.** Hub tells the Mac's updater which apps it may update on its own, and it listed itself as "ask first" — so when one Hub download failed on nine Macs, nothing ever asked again: the fleet's bulk update leaves Hub alone by design, and the partial file sat there for up to three days. Hub now lists itself as automatic, so its own updater retries on its normal check, resuming the part it already downloaded. The owner's automatic-install setting on the Mac still governs what actually installs.

Measured origin: nine Macs carried a Hub `download_failed` for 12.6 h to 3.2 days (`20261120-141`); the transfer resumes a `.part` (`Agent.swift:159` Range request), the agent's sweep only works apps its table marks automatic (`:983-1027`), and the publisher's bulk path excludes Hub (`Server.swift:1424`).

## 0.6.254 — 2026-11-20

- **A job that has gone quiet says so.** Until now a job could sit at "running" for hours with nothing wrong reported, because the attention report only knew about health checks and recent errors. A job silent past its own kind's limit — one hour for pictures, two hours for voice — now appears as needing attention, naming the job and how long it has been quiet. Nothing is cancelled; the job is only reported.
- **An old answer stops reading as today's.** A Mac's row built from a cached snapshot now carries that snapshot's age and says "old snapshot, as of N minutes ago", and the startup check says "last checked N ago" or "not answering" instead of showing a stale green.

- **A model a Mac does not have is called just that.** The Hub used to report "execution unready" for a model whose files were simply not on the Mac, and the Gateway's catalogue repeated that as if the Mac could not run it at all. ## 0.6.253 — 2026-11-19

- **1280×720 is retired for the image model that offered it, and the app says so plainly.** A job asking for that size now gets a sentence, not an error: "The 1280x720 (16:9) size has been retired for FLUX.2 Klein; choose 1024x576 (16:9 small) or 1344x768 (7:4) instead." Pictures already made at 1280×720 are untouched and still open.
- **New jobs start at 1024×576.** That model used to open at 1280×720; with that size retired, the default moved with it, so nothing starts at a size the app no longer offers. Every other shape it offered is unchanged.
- **The catalogue now states what each model can actually render.** Beside the list of sizes offered, each model publishes its engine's own rule (a dimension multiple) and every size it can produce — so another app can answer "what can I pick instead?" from the app's own data rather than guessing.

### Technical notes
- `FLUX2_SIZE_PRESETS` = `SIZE_PRESETS` minus `16:9`, with a comment naming the 2026-11-19 retirement and the source table kept whole for Z-Image and for the way back; `FLUX2_KLEIN` now uses it with default `16:9 small` (1024×576). The retired key raises `The 1280x720 (16:9) size has been retired …`; a replay carrying explicit `width=1280,height=720` is accepted as `custom` so a previously qualified canvas still renders; genuinely unknown ratios keep `Choose a qualified 1K aspect ratio`.
- The row publishes `render_constraints {multiple, min, max, sizes}` beside `image_sizes` (untouched). `sizes` is the authority — every size a model can be asked for by name, derived from `size_presets(model)` so it cannot drift, and it deliberately includes non-multiples of 32 (FLUX2's 1200x800). `multiple` is published **scoped to custom sizes**: `{value: 32, applies_to: "custom", source: "engine"|"policy"}` — the engine's rule where the model declares one (qwen), our canvas policy where it does not (FLUX2). A model-wide claim would say FLUX2 cannot render its own presets, which is false. `min`/`max` are `null` because no model states canvas bounds — no number was invented.
- Tests: `tests/test_retire_1280x720_0253.py` (7), `tests/test_renderable_sizes_0253.py` (2), plus `test_image_sizes_0252`, `test_image_standalone`, `test_image_qwen21` — green. One assertion changed on purpose: FLUX's published default is now (1024, 576).

## 0.6.252 — 2026-11-19

- **One more size, and you can type your own.** Both image models now offer **1024×576** (unchanged default) and **1344×768**, a wider picture that suits 7:4 frames. You can also give a width and height yourself; the app accepts them only when both are multiples of 32, and says which number is wrong when they are not — it never quietly rounds or picks a different size for you.
- **A 7:4 picture is trimmed to 16:9, and the app says so.** 1344×768 is 1.6% narrower than the video frame, so each result is centre-cropped to 1344×756 — a 12-pixel trim, no resizing — and the run records the exact pixels rendered and the crop applied, so a picture is never silently stretched.

### Technical notes
- `7:4: (1344, 768)` added to `SIZE_PRESETS`, `QWEN_SIZE_PRESETS` and `QWEN_MFLUX_SIZE_PRESETS` in `components/image/app/backend/generation.py`; defaults unchanged. The key is its own — never an existing ratio key, and never relabelled `16:9`.
- Both published lists come from `size_presets(model)`: the row's `image_sizes` and `parameters.aspect_ratio.enum`. The Gateway intersects them and silently drops a size present in only one, so `tests/test_image_sizes_0252.py` asserts the key in both for both models.
- `validate_request()` is the door: explicit width/height are accepted only as positive multiples of 32 (`"Width 2050 must be a positive multiple of 32"`), never coerced, rounded or replaced; a pair matching a preset keeps that preset's key, anything else becomes `custom`.
- The crop runs after the engine's PNG is verified, with PIL's crop and no resampling; the job record carries `render_width`/`render_height` (engine pixels) and `crop {source, output, offset}` or `null`, while `width`/`height` stay the delivered pixels. 1344×768 → source [1344,768], output [1344,756], offset [0,6].
- Tests: `tests/test_image_sizes_0252.py` (9), `tests/test_image_standalone.py` (33), `tests/test_image_qwen21.py` (5). Two existing assertions changed because the owner changed the rule: a 2048 width is now a legal custom canvas, and qwen's preset set now includes `7:4`.

## 0.6.251 — 2026-11-19

- **Stopping the app now stops it.** An installer's stop used to look like a crash to macOS, so the app came straight back and a replacement could never finish. A stop now holds new work, lets what is running settle in up to 25 seconds, says what it did in one line, and exits cleanly — so macOS leaves it stopped. A real crash still restarts it.
- **The app's health now says which app answered.** It reports its process id, version, build, when it started, its data folder and how much work is queued, running and uncertain. A reply from the wrong copy is now visible instead of looking healthy.
- **Replacing the app has a supported procedure.** Stop the login service, swap the app, start it again, and verify it answers with the new process id — with a failure path that puts the original back and says so, so a Mac is never left with no start-at-login and no message.
- **An old "start at login" entry that could not be removed is retried.** It used to be reported once and then forgotten, which could leave two login paths forever; now the next launch tries again and keeps saying what to remove.

### Technical notes
- `SIGTERM` no longer re-raises (`native/ShellCore.swift`): a main-queue dispatch source marks the intentional stop and hands off to `handleTerminationSignal()` in `native/StudioHub.swift`, which reads a fresh work count (3 s bound), holds the queue, uses the existing `controller.stop()`/`forceStopWithoutAsking` settle path with the 25 s ceiling (100 ms polls) and exits 0; the ceiling names anything still in flight by id. Crash signals and their markers are unchanged. The lifecycle suite's `term-busy` case exits 133 on the old re-raise and passes now.
- `/api/health` adds `pid`, `version`, `build`, `started_at`, `data_dir` and `queue {queued,running,uncertain}` beside the seven existing keys (unchanged). Queue counts come from `broker.batch_summary()` over `broker.activity_batches()`.
- `packaging/hub-service-lifecycle.sh` (stop/start/verify) and its selftest own a temp launchd label only; observed states: `state = SIGTERMed` → `Could not find service` after bootout; `state = running`, pid matching the health reply after bootstrap; a failed bootstrap (`exit=5 Input/output error`) reports "no service loaded" with the restore instruction and recovers with the original plist. `spawn failed` / `needs LWCR update` are reported verbatim if they occur and did not occur on the temp label.
- `LoginMigration.recordsCompletion(_:)` ends the migration only on success; a caught failure stays unrecorded so the next launch inspects and tries once more (one check, one attempt, nothing on the startup path). Tested both branches in `tests/native/lifecycle_main.swift`.
- Signing: this is the first Hub release under the adopted identity. The two-build `designated =>` comparison and the artifact certificate (read from the mounted DMG) are recorded in the release receipt; no trust setting is added, moved or removed by the build, gate or lifecycle scripts.

## 0.6.250 — 2026-11-19

- **A Mac goes free when its job is done.** A job that had finished could still hold on to the Mac it ran on, so other work waited on a machine that was actually idle. A lease now follows its job: when the job ends, the lease goes with it, and a restarted Hub drops any lease it cannot point at unfinished work.
- **A job with no answer now ends, and says why.** One job waited more than sixteen hours marked "uncertain" with nothing re-driving it. Every uncertain job now ends inside its own limit — failed, with the reason and the option to retry — and if the late answer still turns up it is kept beside the verdict rather than thrown away.
- **A Mac that cannot take work says so on its row.** When the Hub refuses a job because a Mac lacks the memory, the sentence it recorded is shown on that Mac's row with how long ago it was said, and it disappears once the Mac takes work again.
- **The installer's stop never asks a question.** The app used to ask "Quit and stop its engine?" based on whether someone appeared to be watching, which meant a screen-shared Mac stopped for a person while an untouched one sailed through. It now asks only when a person asked to quit: a stop that follows the installer's hold goes straight to holding, settling and quitting.

### Technical notes
- Leases: `broker.prune_stale_machine_leases()` at startup (`restore_batches`) and on the 60 s sweep drops a lease whose owning chat/transcription/developer-test row is absent, terminal or unnamed; a render/peer/relay lease that no local row can disprove is still bounded by `automatic_recovery.MAX_STALL_S` (the existing 6 h ceiling). An idle peer's `machine_lease_busy` refusal reads "peer says lease-busy while reporting 0 running" in `governor_note` and the item error instead of passing the bare 409 up (`peers.reports_zero_running()` reads the existing fresh snapshot only).
- Uncertain: `expire_uncertain_items()` runs on the same sweep and fails an item retryable with `UNCERTAIN_BOUND_EXCEEDED` once its own bound passes — Image 3600 s and Voice 7200 s from `automatic_recovery`, raised by a worker's `deadline_s`, else the existing 21600 s ceiling. A late answer is recorded as `late_result` beside the unchanged verdict.
- Refusals: `broker.note_refusal()` stores `{code, message, at}` in the per-machine protection state at both `INSUFFICIENT_MEMORY` hand-back points, cleared by `_mark_machine_success()`; `fleet_overview()` copies it onto the row as `refusal {code,message,age_s}` and the native row shows it as a caption only while that Mac has no current job.
- Quit: `QuitDecision.shouldChallengeQuit(source:busy:attended:)` — a person's or unknown quit while busy and attended may still be challenged; an installer-sourced stop never is. The source is `/api/health`'s `update_hold_active`, set only by a `POST /api/maintenance/hold` authenticated with the installer's 0600 hold token (`auth.installer_hold_request`) and self-expiring after `dispatch_paused_s`.
- Tests: `tests/test_terminal_lifecycle_0250.py` (7), `tests/test_fleet_refusal_reason_0250.py` (3), `tests/native/lifecycle_main.swift` (the updater-stop case fails without this change — exit 133 on the old attendance gate).

- Tests: `components/voice/app/tests/test_model_audit_contract.py` (26) green, including the moved pin.
