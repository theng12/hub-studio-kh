# Changelog

Plain-language changes appear first in each release and feed the app’s What’s New. Engineering details follow under Technical notes.

## 0.6.261 — 2026-11-25

- **Hub Studio KH keeps itself up to date.** The app now carries its own updater: it reads a signed release feed in the background and installs a new version once you accept it, asking the app to settle what it is doing first so a running job is never cut off, and it reopens by itself afterwards. Nothing opens in front of you while it checks or installs.
- **Preparing this Mac's build no longer fails when it replaces an old copy of the engine it ships.** The step that swaps out a superseded build input could not move a sealed, read-only copy on a Mac whose trash folder lives on the Desktop, and the run stopped halfway. It now retires the old copy to the Desktop trash by its real path, opens a sealed copy before moving it, and no longer files a fresh build as if it were the old one.
- **Nothing about the app you use changes.** This is the build recipe's own repair; the app's screens, models and jobs are exactly as they were.

### Technical notes
- **Sparkle 2.10.1 through the shared KH shim** (`vendor/khsparkle/`: `libkhsparkle.a`, `khsparkle.h`, `Sparkle.framework`, pinned — `shim-pin.sh --check` reports MATCH). `native/build.sh` refuses a build missing any of the three, links `-F`/`-framework Sparkle`/`-L -lkhsparkle`/`-import-objc-header` with `-rpath @executable_path/../Frameworks`, and runs the lifecycle tests with `DYLD_FRAMEWORK_PATH` (outside a bundle, dyld needs it).
- `packaging/stage_voice.py` — the app bundle carries `SUFeedURL` (`https://theng12.github.io/hub-studio-kh/appcast.xml`), `SUPublicEDKey` (this app's own pair at `~/.kh-sparkle/local.studiohub.standalone/public.key`, 44 base64 chars, refusing anything else — a borrowed or guessed key publishes items no Mac can verify), `SUEnableAutomaticChecks`, and the hold pair `KHHoldURL`/`KHHoldTokenFile` on the install hold's own route. `CFBundleVersion` is now the release version, not a constant `1` — Sparkle compares it, so a constant made every release look already installed. `Sparkle.framework` is copied to `Contents/Frameworks` **before** signing, so the existing inside-out walk seals it; `--deep --strict` verifies only.
- `native/StudioHub.swift` — starts the shim after the controller reports `readyURL`, not at launch: cold start used to ask a Hub that was not listening for the hold, be refused, and refuse the update on every launch (two-minute ceiling, the start ladder's own, then one plain log line). It logs `kh-sparkle started` or its refusal reason, and treats a background launch (`STUDIOHUB_BACKGROUND=1` or `--background`) as windowless: no initial window, no failure window, accessory activation policy; a quit the updater initiates is recorded as `.updater`.
- `packaging/appcast.sh` + `docs/appcast.xml` — one item per version, appended by signing **that DMG's exact bytes**, with the version read from the bundle **inside the mounted DMG** and refused when it disagrees with `VERSION` (row `20261125-4`); the written item is re-read and checked before the script reports success.
- `tests/test_khu_agent_staging.py` — updated to the shipped shape it has had since the address scrub: the staged publisher file keeps the pinned key and blanks `feedURL`/`enrolURL`. It was failing on `main` at `d4166203`.
- `packaging/rebuild_build_inputs.sh` — the trash is now `$HOME/Desktop/_trash/<app>/build-inputs-<stamp>` named by the script itself (`KH_BUILD_INPUTS_TRASH` overrides it), never `$ROOT/_trash`; a symlink or a non-directory at that path stops the run with a sentence instead of being traversed; `retire` does `chmod -R u+w` before the move so a builder-sealed (`chmod -R a-w`) tree can be replaced at all; a rebuild that lands in `$BUILD` itself — the canonical checkout, where the builder's `$SOURCE/.build` *is* `$ROOT/.build` — is no longer moved aside and "restored"; `--only` no longer exits 1 when a later input is legitimately absent.
- Cause, measured on 0.6.260's first gate run (issue row `20261125-32`): the checkout carried an `_trash` symlink into the Desktop trash, the YuE2 builder seals its output read-only, and the replacement `mv` answered `Permission denied` after the tree had been rebuilt and normalised. The read-only half is issue row `20261119-20`.
- Tests: `tests/test_rebuild_build_inputs_trash.py` (2) — a read-only input is retired to the override trash and replaced by the tracked one, and a symlinked trash is refused with nothing written through it. `tests/test_appcast_item.py` (2) — an item names the mounted DMG's own version, bytes, URL and signature and refuses a duplicate; a DMG whose bundle disagrees with `VERSION` is refused and leaves no feed. `tests/test_voice_bundle.py` — the staged bundle carries the four Sparkle keys, `CFBundleVersion` = the release version, and `Contents/Frameworks/Sparkle.framework`; its payload digest is now recomputed with `payload_digest` because the vendored framework is real Mach-O and the seal rewrites its signature blobs.


## 0.6.260 — 2026-11-25

- **Every model now states how much RAM it needs before you install it.** The catalogue publishes a real memory figure for every model Hub offers so other Studio apps can show the requirement ahead of time and name the shortfall instead of learning it from a failure.
- **Models that do not fit a Mac are still listed.** A model too large for your Mac stays visible with its memory requirement and shortfall rather than disappearing from the list, and when a real run measures a truer figure the catalogue updates to match while keeping the previous number.

### Technical notes
- `components/hub/backend/model_needs.py` — computes `(needs_gb, needs_source)` for every model, with zero `unknown` entries across all 41 active shipped manifests. `declared` derives from shipped weight bytes plus a constant per-engine runtime overhead (`embed-mlx` / `voice-vits` 0.5 GB; `subtitle-mlx` / `vision-mlx` / `voice-mlx` 1.0 GB; `chat-mlx` / `image-mflux` 2.0 GB; `music-yue2` 2.5 GB; `image-mlx-serve` / `music-mlx` 3.0 GB). `measured` upgrades from worker refusals (`note_refusal`), real loads (`note_load`), manifest `qualification.min_free_memory_gb`, or worker-published free-memory floors, persisting learned values in `model-needs.json` with a bounded `history` preserving replaced figures.
- `components/hub/standalone.py`, `components/hub/backend/model_ids.py`, `components/hub/backend/model_install_plan.py` — publish `needs_gb` and `needs_source` on every model row across `/api/hub/model-packages`, `/api/hub/model-presets`, `/api/hub/catalog`, and `/api/hub/models` without omitting models that exceed a Mac's memory.
- `components/hub/backend/broker.py` — records worker memory refusals through `model_needs.note_refusal` on capacity failures so declared and learned figures converge.
- Tests: `tests/test_model_needs.py` (6) — every active manifest and route entry carries positive `needs_gb` and non-`unknown` `needs_source`, a model that fits nowhere still appears with its `needs_gb` and shortfall, per-engine overhead is constant, and `measured` upgrades preserve prior figures in history.


## 0.6.259 — 2026-11-24

- **Starting several model downloads no longer fails the ones that come after.** The first one runs; anything you start while it runs waits in line and begins by itself, so a 32 GB download and the next click both finish without you going back to them. A refused click is no longer listed under "Finished today" — waiting is not a failure.
- **A drive that goes away pauses the copy instead of failing it.** Plug the drive back in and Resume continues from where it stopped.
- **A preset is one job now.** Installing a preset queues everything it still needs in the same line, and each package starts as the one before it ends.

### Technical notes
- `components/hub/model_downloads.py` — every request becomes a run. `_pump` starts the oldest queued run once no run in that library is active (the lock is per library, so two libraries never wait for each other), and a run whose drive is gone pauses with a reason and a Resume. A child that exits on "Another model import is active" goes back in line up to three times instead of failing, so that sentence can never reach a row a person reads. Cancel works on a waiting run and lets the next one start.
- `components/hub/standalone.py` — `POST /api/hub/model-downloads/{run_id}/resume`.
- The app already treats `queued` and `paused` as active and shows them under Downloading, so the queue needed no native change; the preset button already starts packages one at a time and now queues them.
- `app-meta.json` — the feed generator's first read: name, bundle id, `type media`, tagline, description, and the hold pair (`hold_url` on 47873, `hold_since 0.6.238`).
- Tests: `tests/test_model_download_queue.py` (6) — position and no refusal, self-starting, pause and resume on a lost drive, cancel starting the one behind it, the refusal sentence never in a row, and the bounded wait.

## 0.6.253 — 2026-11-19

- **1280×720 is retired for the image model that offered it, and the app says so plainly.** A job asking for that size now gets a sentence, not an error: "The 1280x720 (16:9) size has been retired for FLUX.2 Klein; choose 1024x576 (16:9 small) or 1344x768 (7:4) instead." Pictures already made at 1280×720 are untouched and still open.

### Technical notes
- `FLUX2_SIZE_PRESETS` = `SIZE_PRESETS` minus `16:9`, with a comment naming the 2026-11-19 retirement and the source table kept whole for Z-Image and for the way back; `FLUX2_KLEIN` now uses it with default `16:9 small` (1024×576). ## 0.6.252 — 2026-11-19

- **One more size, and you can type your own.** Both image models now offer **1024×576** (unchanged default) and **1344×768**, a wider picture that suits 7:4 frames. You can also give a width and height yourself; the app accepts them only when both are multiples of 32, and says which number is wrong when they are not — it never quietly rounds or picks a different size for you.
- **A 7:4 picture is trimmed to 16:9, and the app says so.** 1344×768 is 1.6% narrower than the video frame, so each result is centre-cropped to 1344×756 — a 12-pixel trim, no resizing — and the run records the exact pixels rendered and the crop applied, so a picture is never silently stretched.

### Technical notes
- `7:4: (1344, 768)` added to `SIZE_PRESETS`, `QWEN_SIZE_PRESETS` and `QWEN_MFLUX_SIZE_PRESETS` in `components/image/app/backend/generation.py`; defaults unchanged. The key is its own — never an existing ratio key, and never relabelled `16:9`.
- Both published lists come from `size_presets(model)`: the row's `image_sizes` and `parameters.aspect_ratio.enum`. The Gateway intersects them and silently drops a size present in only one, so `tests/test_image_sizes_0252.py` asserts the key in both for both models.
- `validate_request()` is the door: explicit width/height are accepted only as positive multiples of 32 (`"Width 2050 must be a positive multiple of 32"`), never coerced, rounded or replaced; a pair matching a preset keeps that preset's key, anything else becomes `custom`.
- The crop runs after the engine's PNG is verified, with PIL's crop and no resampling; the job record carries `render_width`/`render_height` (engine pixels) and `crop {source, output, offset}` or `null`, while `width`/`height` stay the delivered pixels. 1344×768 → source [1344,768], output [1344,756], offset [0,6].
- Tests: `tests/test_image_sizes_0252.py` (9), `tests/test_image_standalone.py` (33), `tests/test_image_qwen21.py` (5). Two existing assertions changed because the owner changed the rule: a 2048 width is now a legal custom canvas, and qwen's preset set now includes `7:4`.
