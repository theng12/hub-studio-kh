## Architecture and adoption

The native client connects to the bundled Hub using its owner-only readiness
credential. The Hub owns a private Voice child and uses the same existing token
for local Studio requests. GenStudio/controller/node topology is unchanged; live
fleet connection qualification remains ST-10.

Hub source is adopted at `06e893e1643bffbcbd162fae122e5a4d0f29e283` (2.22.0).
Its retained scheduler, ledger, memory admission, model protection and recovery
modules supply the existing behavior. The packaged entry point omits legacy
Pinokio/Git/update/enrollment lifecycle entry points. Source inventory and deliberate
changes are recorded in [provenance](../research/hub-adoption.json).

Hub and Voice run as separate processes using the same immutable Voice runtime
bytes. The wrapper records real worker ports, PIDs and runtime identity; missing
Image and Subtitle processes are not invented in the registry. Model package files
and mutable device state stay outside the app. The current library has ten pinned
package definitions; file readiness is separate from runtime and admission.
Hub-owned Voice does not start its old independent 80 GiB output cleaner; packaged
Subtitle likewise leaves its inherited independent cleanup timer off. ST-07
supplies the shared protected-output policy; until then this development build
preserves outputs rather than applying an unrelated per-Voice deletion policy.
