### Memory [M]

From the worker's own `/api/chat/diagnostics` after generation:

| Metric | Value |
| --- | --- |
| `active_memory_bytes` | 5,038,041,644 (4.69 GiB) |
| **`peak_memory_bytes`** | **5,216,417,790 (4.86 GiB / 5.22 GB)** |
| Peak process RSS (sampled) | 5.54 GB |

`loaded` was `false` before the first request and `true` after — the engine lazy-loads, as
designed. The earlier receipt's 5.72 GB peak is consistent with this.

### Speed, with its caveat [M]

This run measured the engine's own generation phase: 3 tokens in 1.025 s, 18 in 1.218 s,
24 in 0.973 s. The earlier receipt recorded ≈2.68–2.93 tok/s. **The two are not directly
comparable** — the earlier figure came from a first, cold request that emitted a long
`Thinking Process:` trace, whereas these are short warm completions after the model is
resident. A like-for-like throughput number is still owed (see Outstanding).

## 3. Hub-dispatched generation — PASS [M]

The **real packaged Hub** was started from the same installed bundle with `--offline`. It
brought up all five packaged workers — `voice`, `subtitle`, `music`, `image`, **`chat`** —
each with its own ready file and port. A single authenticated request to the native-facing
route then produced a real completion:

```
POST /api/hub/chat/completions   Authorization: Bearer <hub token>
{"messages":[{"role":"user","content":"In one short sentence, why is the sky blue?"}],
 "max_tokens":64,"temperature":0.2}
```

| Field | Value |
| --- | --- |
| `model` | `mlx-community/Qwen3.5-9B-4bit` |
| `usage` | prompt 23 / completion 24 / total 47 |
| `studio_hub.elapsed_seconds` | 0.973 |
| reply | "The sky appears blue because the Earth's atmosphere scatters shorter wavelengths of sunlight (blue) more effectively than longer wavelengths." |
| shutdown | clean; `0` child processes remained |

This is the end-to-end path the app uses: Hub route → admission/lease → packaged chat worker
→ real MLX model.
