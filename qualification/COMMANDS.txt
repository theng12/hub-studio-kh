STUDIO HUB KH — COMMANDS
========================

HOW TO RUN ANY OF THESE
-----------------------
1. Open Terminal: Applications -> Utilities -> Terminal. A window opens with a
   "%" prompt.
2. Copy a line from this file (select it, Command-C).
3. Paste it into the Terminal window (Command-V) and press Return.
4. Text scrolls out. To send it to me: Command-A to select all, Command-C to
   copy, then paste into the chat.

That is all "run this" ever means. The file sits on the SSD; Terminal is what
runs it. Nothing appears "in" the SSD.

Some scripts print headings like:

    ===== A. WHICH BUILD IS INSTALLED? =====

Those letters are only labels for parts of the output, so we can talk about one
part without quoting everything. They are not special terms.

TURNING OFF OFFLINE MODE (this is what blocks downloads)
--------------------------------------------------------
In the app: Settings -> Model library -> "Use imported models offline" -> OFF.
While it is on, every Download Model button is disabled on purpose, because
downloading needs the internet and offline mode says not to use it.
Importing a folder you already have still works with it on.

------------------------------------------------------------------
0. FIRST: check the app can start
------------------------------------------------------------------
On the Mac that has the app installed:

    sh "/Volumes/KH-STUDIO-ATLAS/Studio Hub App/verify-launch.sh"

It prints RESULT: PASS, or RESULT: FAIL and the reason. Run this before opening
the app. If it fails, copy the whole output back.


------------------------------------------------------------------
1. Install the app, and copy this Mac's models (no typing)
------------------------------------------------------------------
In the kit folder (the one that opens from the SSD):

    double-click  "1 - Install the app.command"
    double-click  "2 - Copy the models.command"

The second one is safe to run any time and is how new models arrive: it copies
models this Mac does not have, updates ones that changed, and leaves identical
ones alone. It also refreshes the app's record, so an updated model is ready
without pressing Verify.

Doing it by hand instead, if a launcher ever refuses to run:

    cp -Rp "/Volumes/KH-STUDIO-ATLAS/Studio Hub App/Studio Hub 0.4.0.app" /Applications/
    sh "/Volumes/KH-STUDIO-ATLAS/Studio Hub App/Technical/copy-models.command"

The models land in ~/Downloads/model-library, and that is the folder to choose
when the app asks. The app reads them from the Mac, so the SSD can be unplugged
afterwards.


------------------------------------------------------------------
2. If macOS refuses to open the app
------------------------------------------------------------------
Right-click the app -> Open -> Open first. If it still refuses:

    xattr -cr "/Applications/Studio Hub 0.4.0.app"

(That prints a wall of "Permission denied" and "No such xattr" lines from the
read-only runtimes inside the app. That is expected and harmless - the files
macOS actually quarantines are cleared before it reaches those. Judge it by
whether the app opens, not by the errors.)

Quieter version, same effect:

    find "/Applications/Studio Hub 0.4.0.app" -path "*/Resources/runtimes" -prune -o -print0 | xargs -0 xattr -d com.apple.quarantine 2>/dev/null; echo done


------------------------------------------------------------------
2b. WHY ARE IMAGE OR SUBTITLE MODELS MISSING?
------------------------------------------------------------------
The app shows a model only when its package is installed AND it is in the
catalog the matching Studio reports. This prints both, per model:

    sh "/Volumes/KH-STUDIO-ATLAS/Studio Hub App/studiohub-check.sh"

In that output, look at section 6b. Send me the whole file if you can. What it
tells us:

  * "manifests found in the app: N" - if this is not 12, the app is missing
    model definitions and needs replacing.
  * The size table: each line shows GB the app expects and GB actually present.
    Anything marked INCOMPLETE was copied only partly - that is the most common
    reason a model is missing, because Finder does not always finish a large
    folder and does not tell you.
  * Each line of the verify list is what the Models screen shows for that model.
    Anything not reading "files_verified" is why it does not appear, and the
    word after it is the reason.

Also useful, the two lists side by side:

    ls "/Volumes/KH-STUDIO-ATLAS/Studio Hub App/model-library"
    ls "/Applications/Studio Hub 0.4.0.app/Contents/Resources/model-manifests"


------------------------------------------------------------------
2c. IMAGE OR SUBTITLE MODELS MISSING — the direct answer
------------------------------------------------------------------
This one uses only the app's own Python, so macOS cannot ask you to install
anything:

    sh "/Volumes/KH-STUDIO-ATLAS/Studio Hub App/why-models.sh"

Read it in this order:
  A. which build is installed - compare it with the line it prints for "newest"
  B. the library the app is pointed at - does it exist?
  C. what is actually in that folder, size and file count per model
  D. each model checked against its record - OK/INCOMPLETE and a state word
     like files_verified. Anything else is why the model does not appear.
  E. any worker failure the Hub logged

None of these scripts need Python installed. If macOS ever offers to install
developer tools, that is a script asking for a system Python 3 that macOS 14
does not have - it is never needed by the app.


------------------------------------------------------------------
2c-bis. IMPORT ALL YOUR OLD VOICES IN ONE COMMAND
------------------------------------------------------------------
No clicking. Point it at the folder that holds your voices:

    sh "/Volumes/KH-STUDIO-ATLAS/Studio Hub App/run-voice-import.sh" "/Volumes/KH-STUDIO-ATLAS/studio-models/voices"

See what it would do first, without writing anything:

    sh "/Volumes/KH-STUDIO-ATLAS/Studio Hub App/run-voice-import.sh" "/path/to/voices" --dry-run

It reads one folder per voice (a clip, and a transcript beside it if you have one). Voices
without a transcript are still imported - they show as needing one, and you can add it in the
app rather than lose the clip.

Then open Voices in the app (or press Refresh) and they are there.


------------------------------------------------------------------
2d. IMPORTING YOUR OLD VOICES
------------------------------------------------------------------
First check they are in a shape the importer reads - one folder per voice,
containing a clip and (for cloning) a transcript file:

    sh "/Volumes/KH-STUDIO-ATLAS/Studio Hub App/check-voices-folder.sh" "/Volumes/KH-STUDIO-ATLAS/studio-models/voices"

Point it at whichever folder holds them. It lists each voice and says whether it
is ready, then in the app: Voices -> Import Folder... and choose the same folder.

A voice with a clip but no transcript is skipped: a clone matches audio to words,
and without them the engine would produce a wrong-sounding voice. Add the words in
the app (Voices -> Edit...) and it becomes usable.

Everything imported is recorded as "Owned by me" with the consent box ticked.

------------------------------------------------------------------

The log file inside it is      hub-worker.log

answer.)
