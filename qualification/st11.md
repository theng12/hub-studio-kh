## ST-11.2 — staged app, kit manifest and rollback input

`packaging/stage_voice.py` produced `dist/Studio Hub 0.4.0.app` with
`development_build: false` — the tree was clean at staging time, so the recorded
`implementation_commit` is exactly the source that was built. Stage while the generated kit
manifest is reverted: it is rewritten after every staging run, so leaving it dirty makes the
next bundle record itself as a development build for no real reason.

Two app-facing checks were run against this exact bundle:

* `POST /api/hub/model-packages/flux2-klein-4b-mlx-4bit/verify` returned `files_verified` with
  `dispatch_state: eligible` — the route behind the Models screen's **Verify Files** button,
  which is the documented remedy for a copied or hard-linked library that reads as changed.
* the Overview's *Measured on this Mac* section reads `/api/hub/stats`; the same receipt that
  drives the run records `total: 1` and a `transcription` matrix row at 18.32 s.
* the **fleet** routes were driven against the bundle: the role reads `standalone`, changes to
  `controller`, and changes back; a node joins and is listed as `unreachable` because nothing
  answers at its address; and a public address is refused with *address must be a private or
  Tailscale address*. This is also where the role-change defect surfaced: the Hub answers
  `PUT /api/hub/controller` with the flat settings object while `GET` answers with the
  `{settings, readiness}` envelope, and the app had decoded the PUT reply as the envelope.
* the Settings **Local storage** section reads `/api/hub/settings` and
  `/api/hub/settings/preview`; the receipt records the effective limits (50 GB, 30 days,
  1 GB minimum free) and this machine's row (`used_bytes: 0`, `protected_bytes: 0`,
  `free_bytes: 423211044864`).
* the fleet overview and the login-start preference were added after this receipt: the
  overview route is now driven by `qualification/evidence/fleet_packaged.py` against two
  packaged Hubs, which asserts one row per Mac with the node's measured work, and the
  preference's default, persistence and legacy-file behaviour are asserted by
  `tests/native/main.swift`.

`packaging/release_kit.py` reads the staged bundle and the library and writes
[focused-release-manifest.json](focused-release-manifest.json): the app's recorded tree hash
and recomputed resource-payload hash, every component's runtime identity, and every advertised
model package with its installed revision, file count and byte size. It exits non-zero when a
package the app advertises is absent from the library at the pinned revision, so a kit cannot
be described as complete when it is not.

Rollback input retained: the previously proven `dist/Studio Hub 0.4.0 Subtitle Proof.app`,
`dist/Studio Hub 0.4.0 Integrated Proof.app`, `dist/Studio Hub 0.4.0 Local Proof.app` and
`dist/Studio Hub Voice Proof.app` are untouched, and `.build/` keeps the runtimes and the
toolchain used to build them. The backup remote `icloud` carries every commit.

## ST-11.IMPORT — configured-source download vs offline copy

Both paths are covered by `tests/test_model_packages.py` and `tests/test_model_downloads.py`
against the same manifests: an imported folder and a downloaded package are validated by the
same `validate_manifest`/`verify_installed` rules and produce the same recorded identity
(package id, pinned revision, per-file digest). Interrupted copies, missing companions and the
symlink/relocation rules are refused with explicit reasons rather than partially accepted.

One real-hardware caveat is recorded on the board: verification is `ctime`-sensitive
(`components/model_packages._stamp()` includes `st_ctime_ns`), so a library file that was
hard-linked rather than copied reports `File changed; verify again` even though the bytes
match. The remedy is a **Verify** pass in the Models screen.

## ST-11.4 — measuring each machine

`qualification/evidence/measure_machine.py` starts the bundle's own Hub and workers, submits
one job per advertised model over the real Hub API, and writes a per-machine receipt with
elapsed time, output identity, peak process RSS and swap state. Every number comes from the
job records the Hub already keeps.

A real run on the build machine (Mac mini M4, 16 GiB, macOS 26.6.2) is recorded in
[machine-macmini-m4-16gb.json](evidence/machine-macmini-m4-16gb.json), covering both a
transcription and an image generation:

| Studio | Model | Job runtime | Output | Wall including startup |
| --- | --- | --- | --- | --- |
| Subtitle | Whisper large-v3-turbo | 23.34 s | SRT artifact | 30.3 s |
| Image | FLUX.2 Klein 4B MLX 4-bit | 94.47 s | 1,122,026 bytes, sha256 `a1fd88f4…` | 97.3 s |

The same run reached the Hub's aggregates for both studios:
`matrix` carries `image` at 94.47 s and `transcription` at 23.34 s on machine `local`, and
`model_rows` carries one row per model.

The receipt reads the Hub's own field names. Output identity comes from `terminal_result`
(verified here: the Image run produced bytes and a digest) and peak worker memory is
`resource_usage.worker.peak_rss_gb`. An earlier version of the harness asked items for
`peak_process_rss_bytes`, which the Hub never publishes, so every receipt carried nulls while
claiming to hold memory data. `peak_worker_rss_gb` is still empty for both studios in this run:
the Image job path does not emit the `imagestudio.resource-telemetry` payload the Hub accepts,
and the Subtitle worker emits no telemetry at all. The receipt now shows that as the Hub's own
field being empty rather than as a reader looking in the wrong place — but **peak memory per
generation is not currently recorded for any studio**, and ST-11.4 should not be read as if it
were.

That run also found and fixed a real defect: `ledger.stats` counts a transcription job from
`activity_events` because a subtitle job produces no asset row, and the dispatcher recorded
only the `running` transition. Every completed Subtitle job was therefore missing from
`total`, `by_machine`, `by_model` and the timeline while the live activity view still showed
it. With the fix, the same receipt now reports `total: 1`,
`by_modality.transcription.count: 1`, `matrix[0].avg_s: 16.99` and a `transcription` point on
the timeline.

**Not done, and not claimed:** runs on any other Mac. RAM tiers, disk sizes and OS versions are
unverified until someone runs the command above on that machine.
