## Repair and evidence

[MEASURED] The existing app's `hub-worker.log` contained a `NameError` at
`job_storage._enforce_budget`: `execution_assets` was imported inside `storage_bytes`,
not the function that calls it. The old regression searched for matching source text
and therefore passed. The replacement executes the real sweep against temporary
assets, verifies expiry deletion, and preserves a live copy. It failed with the same
NameError before the fix.

[MEASURED] Cancellation during the cleanup loop's failure backoff escaped its handler
and aborted Hub shutdown. A test reproduces that cancellation. The handler now covers
the interval, enforcement and retry wait.

[MEASURED] Independent review surfaced three additional issues in the cleanup being
reactivated. Executable temporary-directory tests reproduced refresh-versus-purge
deletion, deletion through a symlinked store, and a malformed deadline stopping the
sweep. The repair serializes the store's mutation/read transactions, refuses a
symlinked root, and skips invalid deadlines while continuing other expiry work.
Both production consumers copy reference bytes under the same lock, so expiry cannot
remove a file between verification and upload/status inspection. This is one Hub's
input-store lock, not a generation or fleet-wide gate.

[MEASURED] Authentication, checksums, generated-output settings, active-job policies,
permanent voice libraries, model files and existing user outputs were preserved.
All deletion tests and packaged cleanup probes use newly created temporary state.
No product dependency was added. This is a correctness repair, not a code-size reduction.
