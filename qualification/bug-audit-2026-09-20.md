### H-01 — P1: launch verifier reports success after failed health check

[MEASURED] **FIXED and integrated through reviewed
[PR #4](https://github.com/theng12/Studio-Hub-KH/pull/4) at `d1db940`.** The verifier
uses the bundled runtime, propagates manifest/readiness/health failures, requires a
JSON object with literal `ok: true`, and preserves child cleanup. The original probe
and seven behavioral tests pass; an independent reviewer reproduced all eight checks.
The defect description below is retained as the audited pre-fix record.

[MEASURED] `qualification/verify-launch.sh:104` invokes **system** `python3`, even
though `$PY` already names the bundled runtime. Lines 109–112 do not assert
`body['ok'] is True`; lines 114–116 print PASS without checking the Python exit code.
The file does not enable shell fail-fast behavior. The fixture supplied an invalid
URL: Python raised `URLError`, yet the shell returned **0** and printed
`RESULT: PASS`. This proves a false-positive verifier, not that the actual app failed health.

Fix: use `"$PY"`, explicitly fail when identity/health checks fail, validate the
health status/body, and pass the manifest path as an argument rather than inserting
an app pathname inside Python source. Preserve isolated state and process cleanup.
Do not rely on `set -e` alone to validate the returned health body.

Acceptance: the existing failing probe passes; missing system Python, malformed
readiness/JSON, health HTTP errors, `ok:false`, and an app path containing an apostrophe
all produce correct nonzero failures. A healthy copied app succeeds using only its
bundled runtime. The script must stop its child on every branch.

### H-02 — P1: accepted Voice job ID is not saved before polling

[MEASURED] **FIXED and integrated through reviewed
[PR #6](https://github.com/theng12/Studio-Hub-KH/pull/6) at `47e7e1c`.** Voice now
persists its pre-POST dispatch fence and accepted receipt before polling, never replays
after a receipt-write failure, retains the physical-machine fence across restart, and
reconciles only the exact uncertain worker job. The original probe, queued/running and
restart/failure regressions, and independent review pass. The pre-fix record follows.

[MEASURED] `components/hub/backend/broker.py:2826` assigns
`item['studio_job_id'] = job['id']`, but the immediate `ledger.save_batch(b)` at
2827–2828 is guarded by `if b['modality'] == 'image'`. The preceding helper at
2472–2475 saves only newly observed execution-start proof, and is called **before**
the accepted ID is assigned. Queued Voice acceptance supplies no such proof.

[MEASURED] The probe executes `_run_item` through a queued Voice acceptance and
captures every `save_batch` before the first polling wait. It observes live ID
`accepted-voice-job` and **zero persisted IDs**. It does not simulate an OS crash;
it establishes the missing durability boundary. A crash before a later successful
write can therefore lose the accepted job reference. Existing recovery code needs
that ID (`broker.py:944–957`), so the next fix must test actual restore behavior too.

Fix: persist accepted Voice identity before polling and handle a failed receipt
write without replaying accepted work. Check the pre-dispatch durability path at
2373–2387 as well; it is also Image-only. Reuse the existing identity/recovery mechanism.

Acceptance: the probe passes for queued and running Voice responses; a forced Hub
restart retains the exact worker ID and reconciles it without another generation
POST. Inject a ledger failure at acceptance and verify no automatic duplicate work.

### H-03 — P1: failed Voice cancellation is published as terminal cancelled

[MEASURED] **FIXED by reviewed
[PR #7](https://github.com/theng12/Studio-Hub-KH/pull/7), product commit `04eef83`.**
Failed or ambiguous cancellation of dispatched Voice work remains `uncertain`, retains
its exact available worker identity and physical-machine fence, and is never replayed.
A confirmed DELETE continues polling the same job and preserves the worker's verified
`done`, `error`, or `cancelled` result. Lease-expired attempts, including a pre-POST
fence whose acceptance receipt is missing, remain uncertain and fail closed to manual
action. Verification passed 73 Hub regressions, nine lifecycle/audit tests, 17 focused
startup/fleet-auth tests, and independent review. The pre-fix record follows.

[MEASURED] `broker.py:1396–1417` returns False when the worker refuses cancellation.
At 2843–2859, `_run_item` ignores that return value and assigns non-Image work
`state='cancelled'`; 2867–2883 contains the corresponding polling path. Image uses
uncertainty handling in those branches. The fixture makes Voice accept a job, then
returns HTTP 500 to the real cancellation helper. Hub state becomes **`cancelled`**
while `cancel_error` is **`worker returned HTTP 500`**.

Fix: retain a nonterminal cancellation/uncertainty state and accepted worker identity
until worker outcome is reconciled. Keep the physical-work reservation while work
may still be active; do not infer successful cancellation from the user's request.
Check both post-acceptance and polling/transport-error paths using existing recovery helpers.

Acceptance: HTTP 500/timeouts during cancel never publish a verified terminal cancel
or free capacity for overlapping work. Eventual worker completion/cancellation is
reconciled once, with the original receipt and no duplicate POST.

### H-04 — P2: fleet worker-route allowlist grants unclassified reads/patches

[MEASURED] **FIXED by reviewed
[PR #8](https://github.com/theng12/Studio-Hub-KH/pull/8), product commit `1576a5f`.**
Fleet-token GET access now names only the scheduling, exact job/artifact, transcription,
and Voice-library reads used by inspected callers; PATCH is limited to saved Voice
metadata. The original probe, 13 targeted matcher/proxy tests, 110 affected backend
tests, and 73 Hub regressions pass. Independent review found no issue after 20 focused
tests, four cross-Hub dispatch/artifact tests, and 18 rejected edge-case requests through
the real middleware. The pre-fix record follows.

[MEASURED] `components/hub/backend/auth.py:404–408` promises that new routes are refused
until classified. Its GET and PATCH regexes at 424 and 427 instead permit every
matching worker `/api/...` path. The real matcher returns **True** for
`GET /studio/voice/api/settings`, `GET /studio/voice/api/not-yet-classified`, and
`PATCH /studio/voice/api/not-yet-classified`. `standalone.py:1184–1220` forwards
permitted calls with the worker's credential. The Voice settings route exists at
`components/voice/app/backend/main.py:859–861`; model-storage reads exist at 681–685.

[MEASURED] This is a verified permission-matcher defect and static reachable-route
inspection. No live credential exploit or secret disclosure was demonstrated. The
Voice settings route serializes public settings; do not describe it as token leakage.

Fix: enumerate the required worker reads and restrict PATCH to intended voice
metadata endpoints. Preserve required catalog, availability, job/result, library,
memory-policy and shared-voice synchronization flows. Inspect actual controller
callers before narrowing the list; do not break fleet operations to satisfy the test.

Acceptance: known required routes still work, arbitrary new GET/PATCH paths are denied,
and protected worker routes return 403 to a fleet token while owner access works.
Test the actual middleware and proxy in addition to the matcher.

### H-05 — P2: Subtitle claims discarded artifacts while final files remain

[MEASURED] **FIXED by reviewed
[PR #9](https://github.com/theng12/Studio-Hub-KH/pull/9), product commit `84fac37`.**
Subtitle now tracks each final path immediately after its atomic rename. Final receipt or
partial multi-format publication failures remove only that job's new files; when cleanup
cannot be confirmed, verified partial receipts and explicit unverified paths persist as
`JOB_PERSISTENCE_UNCERTAIN` through restart. Cancellation classifies cleanup before its
durable terminal receipt. All five original probes, 106 affected Subtitle/Hub tests with
seven real-model skips, 73 Hub regressions, and independent fault-matrix/restart review
pass. The pre-fix record follows.

[MEASURED] `components/subtitle/app/backend/manager.py:520–527` appends temporary
`.part` paths to `staged`, then renames them to final artifacts. On final receipt
save failure, lines 450–455 unlink only `staged` and report
`JOB_PERSISTENCE_FAILED` / `artifacts were discarded`. The fixture fails that exact
final save: **`fixture.srt` remains**, while the recorded message says it was discarded.
The Image equivalent explicitly removes its final path (`generation.py:305–310`).

Fix: track final files created by this job and give a truthful disposition. Remove
only this attempt's newly published files when safe, or keep an explicit uncertain
receipt for reconciliation. Do not silently discard recoverable customer output.
Cover failure partway through publishing multiple formats as well.

Acceptance: after injected final-save failure, either no published artifacts remain
and the failure is truthful, or artifacts remain with `JOB_PERSISTENCE_UNCERTAIN`
and a recoverable identity. Restart must preserve that distinction. Existing tests
cover restart uncertainty but do not exercise this final-save path.
