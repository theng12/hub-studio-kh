### ST-04.3 — the Whisper quality check stays under the parent Voice job lease

The check is **not** a second job. `_validate_qwen_reference_locked` and
`_validate_qwen_output_locked` call `transcription.manager.transcribe_locked(...)`,
which runs in-process with `_lock_already_held=True` under the single global
`_GEN_LOCK` the parent Voice job already owns. There is no HTTP self-call, no
`/api/transcribe` submission, and no second memory-admission lease.

Proven by: `QualityCheckLeaseTests` (lock-held assertion, no `httpx` POST,
cached-evidence short-circuit, transcript mismatch is terminal with no second
attempt) and, at the real boundary, by the single worker log in
`qualification/evidence/st04-qwen-base-worker.log`:
one `Started server process [66364]` for both jobs, two `[gen] starting` /
`[gen] done` pairs in the same process, and three sequential Whisper runs
(one reference validation + one output validation per job) — never two
Whisper processes and never a queued subtitle job.

## 4. Proven vs unproven

**Proven**

- Both Base tiers are cataloged with `voice-cloning`, an audit-bound reference
  profile, `transcript: "required"` and the Whisper quality guardrails; the
  CustomVoice/VoiceDesign tiers are not.
- Reference preparation refuses generic defaults for either Base tier and names
  the model; preset tiers keep their existing fallback.
- Each reference defect gets its own actionable code, with no path/transcript in
  evidence.
- The internal Whisper check runs inside the parent Voice job lease; it cannot
  double-queue or deadlock.
- Voice reference files live outside the generated-output root, and the Hub's
  finalized-output index refuses a reference path.
- Real offline clone inference succeeded for QWEN06 and QWEN17, with the
  reference and output both accepted at TER/CER 0.0.
- The Hub stages a clone reference from local or GenStudio origin through one
  contract, with machine-readable errors, idempotency, expiry bounds, private
  storage, and status reporting.

**Not proven**

- **Physical original-M1 / Sonoma qualification** (ST-11 scope). The receipt
  host is an M4 / 16 GiB / macOS 26.6.2. No 8 GB eligibility is claimed.
- **The 1.7B `min_unified_memory_gb = 16` figure is unmeasured.** The evidence
  on this host shows ~1.84 GiB peak RSS and ~5.25 GiB reported MLX peak for the
  0.6B tier; no memory-floor claim is derived from one 16 GiB machine.
- **Cancellation and offline restart for a Base clone job.** The backend paths
  exist and are covered by retained Voice tests, but no real Base cancellation
  or app-restart receipt was captured in this task.
- **A real end-to-end Hub → Voice clone job with a real model.** The Hub clone
  path is proven to the route/broker boundary (the Broker's multipart streaming
  and error fencing are covered by the retained `test_execution_assets.py`),
  but the assembled Hub + real Base generation was not run.
- **`X-Content-SHA256` on the audio download.** The harness observed no such
  header on either download. Integrity is nonetheless established: the
  downloaded bytes hash to the same SHA-256 the worker recorded as the job's
  final receipt (`c665c5ea…` / `44f218f7…`), which is what
  `qualification/evidence/st04-qwen-base-real-proof.json` records.
- **The `1a010e5` native Audio UI.** Not exercised here; §6 lists the one
  mismatch found by reading it.

## 6. Coordinator must fix (native / Hub integration)

The contract is unchanged from the published one. One real mismatch was found
by reading the native client:

1. **Native sends the staged reference in the wrong place.** `HubAudioRequest`
   in `native/StudioAPI.swift` encodes `voice_reference_asset_id` at the top
   level of the job envelope, beside `model` and `items`. The Broker reads it
   from `shared_params` / item `params` (`components/hub/backend/broker.py`,
   `_run_item`), so before this task the Hub would have dispatched a plain TTS
   request and the Base job would have failed on the worker's reference route.
   I fixed this on the Hub side: `_shared_params_with_local_reference()` folds a
   top-level `voice_reference_asset_id` into the item parameters, with an
   explicit `sharedParams` value taking precedence. **No native change is
   required** — but if you prefer the envelope to be explicit, move it into
   `sharedParams` and the lift becomes a no-op.
2. Everything else in the native client matches the published contract: the
   multipart field is `audio`, `transcript` and `language` are plain fields,
   omitting `sha256`/`source_asset_id` is the documented local origin, and the
   response decoder reads only fields that are always present.
3. Optional hardening: the native `requiresReference` is repo-name based
   (`contains("Base")`). The catalog now ships `reference_audio.declared` and
   `reference_audio.transcript`, which is the same rule expressed as data;
   consider switching so a future catalog change cannot drift from the UI.
4. **Staging**: `packaging/stage_voice.py` already ships
   `components/voice/model-audits` as `Resources/voice/model-audits`, which is
   what the audit-bound reference contract needs. Do not drop it: without those
   records the worker correctly refuses to prepare a Qwen Base reference with
   `REFERENCE_AUDIO_CONTRACT_UNAVAILABLE`.
