# ST-14 — Local Chat Studio (MLX text model)

Status: IN PROGRESS · Owner/session: direct owner request 2026-09-24 · Prerequisites: ST-01, ST-02

Owner direction (2026-09-24): stock a local language model and add a real **Chat** Studio to
the standalone app, taking it out of the "Coming later" sidebar, then expose it so Story Studio
KH can generate scripts, outlines, thumbnail/image prompts and metadata locally.

Owner-selected shape (2026-09-24):

- **Runtime: MLX first** (`mlx-lm`), matching the app's MLX-only architecture.
- **Order: local Chat Studio + stocking first**, Story Studio bridge second.
- **Model: `Qwen3.5-9B` only** — `mlx-community/Qwen3.5-9B-4bit` at
  `8b2b98c00a6b4d291155e4890773ca8f769aee53` (uniform 4-bit MLX, 5.98 GB); text-only accepted
  (the one vision call stays on the cloud). **Revised 2026-09-24 from the OptiQ build:** the
  OptiQ index references `optiq/optiq_vision.safetensors` as a required shard rather than an
  optional adapter, so its complete snapshot is 8.22 GB; the plain MLX build is the same
  `qwen3_5` architecture with a byte-identical chat template at 5.98 GB and no sidecars, which
  is the better fit for the 16 GB-first fleet. OptiQ stays the higher-quality option if the
  owner wants it on the 24/32 GB machines. Rationale and alternatives:
  `research/story-text-llm-shortlist.md`; the owner decision is recorded in
  `research/owner-hardware.md`.

**Scope note.** `docs/standalone-plan.md` deliberately defers Chat. This card supersedes that
deferral **for Chat only**, exactly as Music was added after its own deferral.

**Serialization with ST-13 (pocket-tts / TTS pruning), 2026-09-24.** ST-13 is concurrently
active and owns `model-manifests/`, `packaging/capture_model_manifests.py`, the four kit
libraries and shared staging. The following steps are therefore **gated on ST-13 landing** and
must not be edited concurrently: `packaging/capture_model_manifests.py` `CHOICES`/`DETAILS`,
`packaging/stage_voice.py`, `packaging/hub_worker.py`, all four SSD kit libraries and the Mac
model library. ST-14 starts with the non-conflicting slice: a new `components/chat/` worker and
a real local MLX completion proof.

## Recon — 2026-09-24

- The Hub is already chat-aware: `capabilities.py` maps `chat → chat.completion`, and
  `memory_control.SUPPORTED_MODALITIES`, `ledger` operation types and `broker` all know chat.
- `components/hub/backend/chat_jobs.py` is a restart-safe chat queue, but it is the
  **external/GenStudio** lane ("adaptive scene-prompt packs"): it uses `studio_request` and
  `broker.note_external_dispatch`, not a packaged local worker.
- `packaging/hub_worker.py` `worker_specs()` builds only voice, image, subtitle and music
  workers. There is no `components/chat/`, no `packaging/chat_worker.py`, and no chat runtime.
- No local Hub chat route (`/api/hub/chat…`) exists.
- Native: `StudioPage.chat` exists but sits in `StudioPage.comingLater = [.video, .chat]`
  (`native/ShellCore.swift`), and `workspaceStatus` excludes chat, so it reads
  "Engine not installed" (`native/StudioViews.swift`).
- **The upstream Chat Studio source is not on this machine.** `/build` does not
  exist here and there is no `chatstudio-mac` checkout under `~/Developer`, so this card builds
  a minimal MLX worker following the existing worker pattern instead of adopting an
  unavailable legacy codebase.
- `.build/voice-runtime` already carries **mlx 0.31.2 / mlx-lm 0.31.3**, matching the lock the
  upstream Chat Studio used — no new MLX version is required.
- **Model download is network-bound on this machine.** The chosen snapshot is 5.98 GB
  (`model-00001` 5.35 GB, `model-00002` 0.60 GB, tokenizer/vocab ~27 MB, config/template).
  Measured HF CDN and `hf-mirror.com` both deliver ≈75–96 KB/s here, so the weights cannot be
  fetched in-session. The **manifest is captured from metadata** (fast) and the weights are
  loaded/stocked on a normal connection through the app's own download path or the kit.
- **`mlx-lm 0.31.3` ships `qwen3_5` and `qwen3_5_moe`** (`mlx_lm/models/qwen3_5.py`, which also
  handles `vision_tower` keys), so the MLX-first runtime supports this checkpoint. Validated
  against the real pinned files: `text_config.max_position_embeddings` = 262144 parses through
  the engine's nested lookup, and the real tokenizer renders the model's own chat template
  (byte-identical between the plain and OptiQ builds).

## Design (smallest implementation that proves the requirement)

- `components/chat/app/backend/main.py` — single-model MLX chat service: `/health`,
  `/v1/chat/completions` (streaming and non-streaming), model load/release, memory telemetry,
  and published `context_window_tokens` / `max_output_tokens`.
- `packaging/chat_worker.py` — owned-worker entry point mirroring `image_worker.py` /
  `voice_worker.py` (readiness + owned shutdown). **Gated on ST-13 for staging edits.**
- `packaging/hub_worker.py` — add a chat spec (`id: chat`, `modality: chat`). **Gated.**
- `packaging/stage_voice.py` — stage `components/chat` + chat runtime identity. **Gated.**
- Hub — a **local** chat job route plus admission/ledger/monitor and a Model-memory entry. The
  existing external `chat_jobs.py` lane is kept separate or retired deliberately; the two are
  never silently merged.
- `model-manifests/qwen3-5-9b-4bit.json` — captured at the pinned revision with exact file
  SHA-256, engine `chat-mlx`, 11 files / 5,977,071,067 bytes. Package ids forbid dots, so the
  id is `qwen3-5-9b-4bit`. **Captured and validated; staged at
  `.build/chat-stage/model-manifests/` so the shared catalog test does not go red while ST-13
  prunes. The `CHOICES`/`DETAILS` registration and the catalog-test `EXPECTED` row are gated
  on ST-13.**
- `qualification/copy_models_for_this_mac.py` — fit/stock via the manifest; no `PROVEN_SMALLER`
  claim without a measured run.
- `native/StudioViews.swift`, `native/ShellCore.swift` — move `.chat` out of `comingLater`,
  build the Chat workspace, include chat in `workspaceStatus`. Serialize with native owners.
- ST-14.6 — expose the local model to gateway-kh for Story Studio, including the open
  `lmstudio:` prefix / two-pass-planning question.

3. `packaging/capture_model_manifests.py` — add the `CHOICES` row and `DETAILS` entry (engine
   `chat-mlx`; no exclusions — the plain build has no optional sidecars).

5. `packaging/hub_worker.py` — **already landed**: the chat spec is guarded on
   `'chat' in release.get('components', {})`. `packaging/stage_voice.py`, inside
   `if include_hub:`, next to the Subtitle block:

   ```python
   chat_source = resources / 'components/chat'
   copy_tracked_tree(ROOT / 'components/chat', chat_source)
   shutil.copyfile(ROOT / 'packaging/chat_worker.py', resources / 'chat_worker.py')
   release['components']['chat'] = {
       'source_sha256': tree_digest(chat_source), 'runtime': 'voice',
       'runtime_sha256': release['runtime_sha256'],
   }
   ```

   Keep it in the same change as the manifest copy so the guarded spec can only activate on a
   complete bundle.
