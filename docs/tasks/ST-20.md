# ST-20 — the lane execution contract (Gateway Studio's ask)

**Status:** DONE in 0.6.61, 2026-09-25. The four behavioural asks (1, 2, 4 and the measured
limits) are delivered and verified; video (3) stays a forward declaration until a video worker
ships. Re-verified against the tree at `2440a35` the same day: the Voice lane's runtime table is
now a stored record rather than code, and its one remaining open item (Pocket TTS preset voices)
is a **won't-fix** by the owner's decision. What remains open is listed at the end.

## Why

Gateway Studio — the sibling project that schedules work onto Hub nodes — asked for this by name in
`_handoffs/2026-09-25-studio-hub-lane-contract-prompt.md` (committed there as `1ad796e`). Their
framing is the whole justification:

> Discovery is already solved — the gateway now reads the modality the Hub states, so a model on a
> new engine arrives instead of vanishing. Dispatch is not, and that's the ask.

A scheduler can learn *that* a lane exists from a modality string. It cannot learn what to send,
what comes back, which states are terminal, or what a cancel means. Today it guesses those from an
engine table, and a guess is what produced the silent model drop the modality field just removed.
With a published contract, a new lane is a data change on the Hub side and **no gateway release**.

The shape is specified in `docs/lane-execution-contract.md`. That file is the contract; this card is
the work.

## What the contract states, in one place

- `operation` — the canonical token from `capabilities.OPERATION_BY_MODALITY`, so it joins to the
  Hub's namespace. (Music's worker label is `music.text_to_music`; the canonical token is
  `music.generation`, and the Hub keeps the worker's wording in `hub_reported_operation`.)
- `parameters` — the **asked-for** surface with `type`, `required`, and the bound that is actually
  enforced, built from the model's own limits. A parameter the lane ignores or refuses is **not**
  listed.
- `artifact` — `modality`, `media_type`, `extension`, `per_item`.
- `states` — `accepted` / `active` / `terminal`, plus `uncertain` and the explicit
  `uncertain_is_terminal: false`. `uncertain` is held for an operator decision; a scheduler that
  treats it as finished either loses an artifact or double-charges a machine.
- `cancel` — the request shape and, in `semantics`, what it does **not** promise.
- `runtime_seconds` — what one item costs, **only where measured**, as a list of rows so a lane
  whose cost depends on a request parameter publishes the same shape as one whose cost does not.
  Absent means unmeasured; a guessed runtime is how a scheduler sets a deadline that fails on use.
  The Voice lane now reads its numbers from a **stored record** rather than a table in its own
  source — see [below](#runtime_seconds-is-read-from-a-stored-record).
- `deadline_seconds` — added by the **Hub**, not the worker: the value is the Hub's own peer-proxy
  timeout (`standalone.PEER_PROXY_TIMEOUT_S`, `components/hub/standalone.py:41`), one constant owned by
  the party that enforces it. **This document deliberately does not restate the number** — it was
  written as "the 900 s" against `standalone.py:1867`, and both the value and the line drifted. Read
  the constant; the Hub publishes whatever it currently holds a job to.

## `runtime_seconds` is read from a stored record

Re-verified 2026-09-25, and the Voice lane's last curated table is gone. What changed:

- `components/voice/app/backend/lane_contract.py` no longer carries `_MEASURED_RUNTIME`, a
  repo-keyed map whose numbers existed only as prose in `catalog.py`'s comments. It now reads
  `qualification/evidence/voice-runtime-2026-09-25/measured-runtimes.json`, whose rows name the
  probe file each number came from, and falls back to the model's own audit record
  (`components/voice/model-audits/`, shipped) where one states a run.
- **A model with no stored receipt publishes nothing.** Two entries were dropped for that reason:
  VoxCPM2 4-bit (MLX 4-bit)'s fleet wall-clocks (61.9 s / 738.4 s, 2026-08-07 — prose in the
  changelog and the catalog comment, no probe) and Pocket TTS 4-bit (MLX 4-bit)'s 0.30 s
  (prose in a manifest's `memory_evidence` and the owner-review notes, no probe). Every model
  whose run *is* stored keeps a number: five models publish six `r07-2026-09-21`-backed rows
  (VoxCPM2 4-bit ×2, VoxCPM2 8-bit, VoxCPM2 bf16, OmniVoice bf16, Qwen3-TTS 12Hz 0.6B Base
  8-bit), and Qwen3-TTS 12Hz 1.7B Base 4-bit keeps its audit-canary runtime.
- The record is a build-time artefact: a packaged worker is not shipped the `qualification/`
  tree, so in the bundle only audit-backed runtimes appear. Absent is the honest value, and a
  copy in the worker is what this change removed.

## Measured model limits (ask 4)

`mlx-community/Qwen3.5-9B-4bit` publishes `text_config.max_position_embeddings = 262144` in its own
`config.json` **[M]**, which `llm_engine.py` already reads. The checkpoint ships **no**
`generation_config.json`, so `max_output_tokens` is the worker's own `4096`
(`FALLBACK_MAX_OUTPUT_TOKENS`) and is published as a worker default, not as the model's number.
Gateway was publishing a curated flat `1,000,000 / 128,000`; the fix is not a better curated number
but provenance beside every value and **no value at all** where nothing states one.

Related defect fixed in the same pass: `model-manifests/qwen3-5-9b-4bit.json` pointed
`defaults.parameters_source` at `model/generation_config.json`, a file neither the package nor the
publisher ships — a dead pointer to the very file the limits would have come from.

## Open after 0.6.61

1. **Pocket TTS 4-bit (MLX 4-bit)'s eight preset voices — WON'T FIX (owner, 2026-09-25).** It ships
   them (`pocket-tts-preset-voices`: `alba`, `azelma`, `cosette`, `eponine`, `fantine`, `javert`,
   `jean`, `marius`) and also declares cloning, so it lands in one tab only. The owner: *"pocket
   tts's 8 eight can be skipped. it's not needed as long as it has voice clone."* The model ships
   cloning and that path works, so the `preset_speakers` roster derived from that package's own
   file names, and the preset picker, are **not being built**. The producer still publishes
   `modes: ["cloning", "preset"]` for this row — the mode is real, the *named roster* is what is
   skipped — and the native page decides what to render from `modes`, not from a repo name.
2. **The audited-reference-audio profiles are being extended by a separate worker.** Reference
   preparation refuses by name for VoxCPM2 (4-bit/8-bit/bf16), Chatterbox 8-bit, Fish S2 Pro
   (8-bit/bf16) and Pocket TTS 4-bit today, because those profiles must be measured rather than
   guessed; that work owns `reference_audio.py` / `main.py` / `generation.py` and is tracked
   there, not here.
3. **An unannotated studio row still falls back to capability tokens** for chat detection. The
   durable fix is that every studio row carries the Hub's own `hub_modality`, which it already
   adds — the fallback should be deleted once no producer needs it.
4. **Video.** `docs/lane-execution-contract.md` carries the forward declaration and the one route
   the Hub has (text-to-video). No contract is published until a worker exists to enforce it.
