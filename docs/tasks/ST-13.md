## ST-13.A — pocket-tts adoption

Upstream, verified by HF API on 2026-09-24:

- Weights: `mlx-community/pocket-tts-4bit` @ `59592598c532759d2b66a3d8905a612dcbe8419c`
  (not gated). Files: `config.json`, `model.safetensors`, `model.safetensors.index.json`
  (plus README/.gitattributes, which the catalog excludes).
- Engine: `mlx-audio` `pocket_tts` — already supported; generation is
  `generate(text, voice=None, ref_audio=None, ...)` so it does **preset voice or clone**.

**The wrinkle.** `config.json` names its sentencepiece tokenizer by URL, not by a local file:

```
hf://kyutai/pocket-tts-without-voice-cloning/tokenizer.model@d4fdd22ae8c8e1cb3634e150ebeff1dab2d16df3
```

`mlx_audio`'s `download_if_necessary()` resolves that against the Hugging Face cache. The
archive copy under `model-library/voice-models/pocket-tts-4bit/` does **not** contain
`tokenizer.model`; the clip generated during the review worked only because that file was
fetched into `~/.cache/huggingface/hub/models--kyutai--pocket-tts-without-voice-cloning/`.
**An offline kit will fail without it.** The adoption must therefore ship the tokenizer as a
companion:

- New companion package `pocket-tts-tokenizer`:
  `kyutai/pocket-tts-without-voice-cloning` @ `d4fdd22ae8c8e1cb3634e150ebeff1dab2d16df3`,
  single file `tokenizer.model`; declare it in the pocket-tts manifest's `dependencies` and add
  a `FAMILY_COMPANIONS["pocket-tts"]` entry so the app seeds the HF cache the way it already
  does for SNAC, UMT5, S3Tokenizer and the Fish/MOSS codecs.

## Decisions that close work rather than leave it open — 2026-09-25

1. **Pocket TTS 4-bit (MLX 4-bit)'s eight preset voices are a won't-fix.** The owner: *"pocket
   tts's 8 eight can be skipped. it's not needed as long as it has voice clone."* The model ships
   cloning and that path works (measured on this host: 6.64 s of audio in 0.30 s, 1.93 GB peak,
   with the preset path at 0.25 GB). So the `preset_speakers` roster derived from
   `pocket-tts-preset-voices`'s own file names — and the mode-picker half of that work — is
   **not being built**. Do not reopen it as a defect. The producer does still publish the mode:
   `catalog.serialize_model` now carries `modes: ["cloning", "preset"]` for this row, because the
   family's resolver genuinely reads its `voice` field; a *named* roster is what is skipped, not
   the mode.
2. **The audited-reference-audio refusal is being made functional by a separate worker.** The
   profiles exist only for the Qwen families today, so private reference preparation refuses by
   name for VoxCPM2 (4-bit/8-bit/bf16), Chatterbox 8-bit, Fish S2 Pro (8-bit/bf16) and Pocket TTS
   4-bit instead of using a guessed 24 kHz/no-max copy. That work owns
   `components/voice/app/backend/reference_audio.py`, `main.py` and `generation.py`; this card does
   not track it, and it is not a Voice-menu defect.
3. **Pocket TTS 4-bit (MLX 4-bit) lost its published runtime** in the same pass, for the honest
   reason: the 0.30 s figure exists only as prose. See
   [ST-20](ST-20.md#runtime_seconds-is-read-from-a-stored-record) and
   `qualification/evidence/voice-runtime-2026-09-25/measured-runtimes.json`.

## The voice smoke pilot — 2026-09-25

The stale record is fixed and the smoke now runs *up to the model*, but it cannot complete on the
artifact it is built around. Facts, in order:

- `qualification/model-inputs.json` keeps the 0.1.0 `models` array untouched as evidence and adds
  `shipped_smoke`: **Qwen3-TTS-12Hz-0.6B-Base-8bit (MLX 8-bit)** with `smoke_params
  {language: en, seed: 42}` and the tracked reference clip. No `preset_speaker` is recorded -
  Qwen3-TTS Base publishes no preset-speaker roster; that roster belongs to the CustomVoice family
  this catalog does not ship. The Whisper ASR entry is recorded there too, because the historical
  one listed `.gitattributes`/`README.md`, which the package import does not copy into the cache.
- `packaging/smoke_voice.py` reads that entry, verifies the pilot snapshots by hash, and starts the
  worker from the worker's **own ready file**. The old readiness check matched uvicorn's
  `Uvicorn running on …` log line, which uvicorn does not print when the worker supplies its own
  sockets (`uvicorn/server.py`) - so the smoke could not see a worker that had started, and waited
  out its 60 s instead. Measured: with the ready file it reaches `/api/catalog` in ~2 s.
- **Where it stops, and why it is not a model problem.** The clone job reaches the engine's
  reference preparation (audited profile, derived WAV `2bc3ecd3…`, 5.166 s) and then fails with
  `QWEN_VALIDATOR_MODEL_UNDECLARED`: `qwen_quality.validator_repo` reads the model's own
  `requires_packages` from `model-manifests/`, and `packaging/stage_voice.py::_stage_voice` stages
  **no `model-manifests/`** into a voice-only bundle (the hub stage does, which is why the shipped
  app works). The same missing tree stops the ASR leg:
  `transcription.whisper_processor_repo` needs the manifest or a `_name_or_path` the mlx snapshot
  does not carry.
- **Exact fix, in a file this card does not own:** stage `model-manifests/` in `_stage_voice`, the
  way `_stage_hub` already does. Until then a voice-only artifact cannot pass the smoke, and the
  two failures are by name rather than silent.
- **The recorded parameters themselves are proven.** Run through the hub-inclusive 0.6.61 bundle on
  this host with the same clip, text and parameters: state `done`, 230,444-byte WAV at 24 kHz,
  24.26 s for the job. Receipt:
  `qualification/evidence/voice-runtime-2026-09-25/qwen06-base-8bit-smoke-clone.json`, produced by
  `hub-job-probe.py` beside it. That receipt is also published as the model's newest runtime row.
