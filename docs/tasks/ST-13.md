## ST-13.A — pocket-tts adoption

Upstream, verified by HF API on 2026-09-24:

- Weights: `mlx-community/pocket-tts-4bit` @ `59592598c532759d2b66a3d8905a612dcbe8419c`
  (not gated). Files: `config.json`, `model.safetensors`, `model.safetensors.index.json`
  (plus README/.gitattributes, which the catalog excludes).
- Engine: `mlx-audio` `pocket_tts` — already supported; generation is
  `generate(text, voice=None, ref_audio=None, ...)` so it does **preset voice or clone**.

**The wrinkle.** `config.json` names its sentencepiece tokenizer by URL, not by a local file:

```
hf://kyutai/pocket-tts-without-voice-cloning/tokenizer.model@d4fdd22ae8c8e1cb3634e150ebeff1dab2d16df3
```

`mlx_audio`'s `download_if_necessary()` resolves that against the Hugging Face cache. The
archive copy under `model-library/voice-models/pocket-tts-4bit/` does **not** contain
`tokenizer.model`; the clip generated during the review worked only because that file was
fetched into `~/.cache/huggingface/hub/models--kyutai--pocket-tts-without-voice-cloning/`.
**An offline kit will fail without it.** The adoption must therefore ship the tokenizer as a
companion:

- New companion package `pocket-tts-tokenizer`:
  `kyutai/pocket-tts-without-voice-cloning` @ `d4fdd22ae8c8e1cb3634e150ebeff1dab2d16df3`,
  single file `tokenizer.model`; declare it in the pocket-tts manifest's `dependencies` and add
  a `FAMILY_COMPANIONS["pocket-tts"]` entry so the app seeds the HF cache the way it already
  does for SNAC, UMT5, S3Tokenizer and the Fish/MOSS codecs.
